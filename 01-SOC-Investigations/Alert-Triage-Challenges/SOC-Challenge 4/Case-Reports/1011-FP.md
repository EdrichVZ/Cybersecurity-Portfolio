# Alert 1011: Phishing Website Blocked

## Incident Classification

**False Positive**

## Escalation Required?

**No**

## Case Report

### Time of Activity

`09/08/2026 20:00:01.445`

### Affected Entities

| Entity | Details |
| :--- | :--- |
| **User** | `yani.zubair` — IT Admin |
| **Source Host** | `Lin-005` — `192.168.0.14` |
| **Destination IP** | `185.29.114.159` |
| **Destination URL** | `http://zo0m.us` |
| **Device / Service** | Firewall |

### Reason for Classifying as False Positive

The alert was triggered by the firewall's `Block-Phishing-Sites` rule when `Lin-005` (`192.168.0.14`) attempted to access `http://zo0m.us` over HTTP.

The asset inventory identifies `Lin-005` as the workstation assigned to IT administrator Yani Zubair. The SOC handover notes also document that Yani Zubair is actively conducting **authorized attack simulation testing using the AtomicRed framework**, which is expected to generate false positive security alerts.

Given the ongoing authorized security testing on this host, the attempted connection is consistent with the documented testing activity rather than genuine phishing activity.

### Reason for Not Escalating the Alert

Escalation is not required because the activity originated from the workstation of the IT administrator currently conducting **authorized AtomicRed security testing**.

Additionally, the firewall successfully **blocked the connection**, preventing access to the destination and resulting in no identified security impact.

### Recommended Remediation Actions

- Close the alert as a **False Positive** related to authorized IT security testing.
- Continue monitoring activity from `Lin-005` to ensure subsequent alerts remain consistent with the approved AtomicRed simulation.
- Consider documenting domains and network activity expected during the AtomicRed testing to assist with future alert triage.
