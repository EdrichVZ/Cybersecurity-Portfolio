# Alert 1012: Phishing Website Blocked

## Incident Classification

**True Positive**

## Escalation Required?

**No**

## Case Report

### Time of Activity

`09/08/2026 20:05:06.445`

### Affected Entities

| Entity | Details |
| :--- | :--- |
| **User** | `cain.omoore` — Sales |
| **Source Host** | `Lin-007` — `192.168.0.16` |
| **Destination IP** | `202.88.154.245` |
| **Destination URL** | `http://hatsh0p.com` |
| **Device / Service** | Firewall |

### Reason for Classifying as True Positive

The alert was triggered by the firewall's `Block-Phishing-Sites` rule when internal host `192.168.0.16` attempted to access the phishing URL `http://hatsh0p.com` over HTTP.

The asset inventory correlates `192.168.0.16` to `Lin-007`, assigned to Cain Omoore in the Sales department.

This is classified as a **True Positive** because the workstation attempted to communicate with a destination identified by the firewall as a phishing website. The firewall successfully intercepted and blocked the connection before the user could access the malicious content.

### Reason for Not Escalating the Alert

Escalation is not required because the firewall successfully **blocked the connection** before access to the phishing website occurred.

According to SOC guidelines, a phishing threat that is successfully blocked before causing user or system impact does not require further escalation. No evidence of successful access, credential compromise, malware execution, or secondary malicious activity was identified.

### Recommended Remediation Actions

- No immediate technical remediation is required on `Lin-007`, as the connection was successfully blocked by the firewall.
- Consider providing targeted security awareness training to `cain.omoore` regarding suspicious links and phishing websites.
- Continue monitoring `Lin-007` for additional attempts to access suspicious or malicious destinations.
