# Alert 8815: Possible Brute Force Attack on SSH

## Incident Classification

**True Positive**

## Escalation Required?

**No**

## Case Report

### Time of Activity

`09/08/2026 17:37:31.593`

### Affected Entities

| Entity                  | Details                                |
| :---------------------- | :------------------------------------- |
| **Target Host**         | `192.168.100.38` — `prod` (Web Server) |
| **Target User Account** | `admin`                                |
| **Attacking IP**        | `182.132.25.71`                        |

### Reason for Classifying as True Positive

An external IP address (`182.132.25.71`) executed **multiple failed SSH authentication attempts** against the internal web server (`192.168.100.38`) targeting the `admin` account.

This indicates **automated brute-force activity** against the SSH service.

### Reason for Not Escalating the Alert

Escalation is not required per SOC guidelines. While the alert represents **genuine malicious brute-force activity**, all authentication attempts failed and no successful breach or secondary compromised behavior occurred on the host.

### Recommended Remediation Actions

* Add external IP `182.132.25.71` to the **edge firewall blocklist**.
* Ensure SSH access on the production web server (`prod`) is restricted to **management subnets** or protected by rate-limiting tools such as **Fail2ban**.
* Enforce **public key authentication** and disable direct root/admin SSH logins where applicable.

| **Source Port**      | `34262`          |
| **Destination IP**   | `192.168.100.38` |
| **Destination Port** | `22` (SSH)       |
| **Target Account**   | `admin`          |
| **Service/Process**  | `sshd[4854]`     |

## Analyst Verdict

**Classification:** True Positive
**Escalation:** No

The alert was confirmed as a **brute-force attack against the SSH service**. Multiple authentication attempts were made against the `admin` account from an external IP address, but all attempts failed. No evidence of successful authentication or further compromise was identified.
