# Alert 8818: Possible Brute Force Attack on SSH

## Incident Classification

**True Positive**

## Escalation Required?

**No**

## Case Report

### Time of Activity

`09/08/2026 17:43:51.593`

### Affected Entities

| Entity                  | Details                                |
| :---------------------- | :------------------------------------- |
| **Target Host**         | `192.168.100.38` — `prod` (Web Server) |
| **Target User Account** | `admin`                                |
| **Attacking IP**        | `182.132.25.71`                        |

### Reason for Classifying as True Positive

An external IP address (`182.132.25.71`) executed **additional failed SSH authentication attempts** against the production web server (`192.168.100.38`) targeting the `admin` account.

This constitutes **ongoing automated SSH brute-force activity**.

### Reason for Not Escalating the Alert

Escalation is not required per SOC guidelines. While the activity represents a **True Positive brute-force attempt**, all authentication attempts failed, and no successful login or compromise occurred.

### Recommended Remediation Actions

* Add external IP `182.132.25.71` to the **edge firewall/perimeter blocklist** to prevent further automated noise.
* Ensure SSH access on `prod` (`192.168.100.38`) is protected by automated **rate-limiting solutions** such as Fail2ban.
* Verify that direct **root/admin SSH logins are disabled** in favor of key-based authentication.

## Analyst Verdict

**Classification:** True Positive
**Escalation:** No

The alert was confirmed as **ongoing automated SSH brute-force activity** originating from `182.132.25.71`. Additional authentication attempts were made against the `admin` account, but all attempts failed. No evidence of a successful login or system compromise was identified.
