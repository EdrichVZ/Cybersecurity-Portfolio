# Alert 1014: Hacking Website Blocked

## Incident Classification

**False Positive**

## Escalation Required?

**No**

## Case Report

### Time of Activity

`09/08/2026 20:17:58.445`

### Affected Entities

| Entity | Details |
| :--- | :--- |
| **User** | `yani.zubair` — IT Admin |
| **Source Host** | `Lin-005` — `192.168.0.14` |
| **Destination IP** | `162.159.244.38` |
| **Destination URL** | `https://shodan.io` |
| **Device / Service** | Firewall |

### Reason for Classifying as False Positive

The alert was triggered by the firewall's `Block-Hacking-Sites` rule when `Lin-005` (`192.168.0.14`) attempted to access `https://shodan.io` over HTTPS.

The asset inventory identifies `Lin-005` as the workstation assigned to IT administrator Yani Zubair. The SOC handover notes specifically document that Yani Zubair requested `https://shodan.io`, along with `https://exploit-db.com` and `https://abuseipdb.com`, to be added to the whitelist for legitimate IT use.

The activity is therefore consistent with **authorized IT activity**, and the alert was generated because the requested whitelist configuration had not yet been correctly implemented.

### Reason for Not Escalating the Alert

Escalation is not required because the destination was **explicitly approved for legitimate use by the IT administrator** according to the SOC handover notes.

Additionally, the firewall successfully blocked the connection. There is no evidence that the activity represents unauthorized or malicious behavior.

### Recommended Remediation Actions

- Close the alert as a **False Positive**.
- Update the firewall configuration to whitelist `https://shodan.io` for `Lin-005` as previously requested.
- Verify that the other requested security resources, `https://exploit-db.com` and `https://abuseipdb.com`, are also correctly whitelisted to prevent recurring false positive alerts.

## Analyst Verdict

**Classification:** False Positive  
**Escalation:** No

The alert was determined to be a **false positive caused by legitimate IT access to Shodan being blocked by the firewall**. The source host belongs to IT administrator Yani Zubair, and the SOC handover notes explicitly document that `https://shodan.io` was requested to be whitelisted for legitimate use. No evidence of malicious or unauthorized activity was identified.
