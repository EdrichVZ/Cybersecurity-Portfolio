# Alert 1006: Phishing Website Blocked

## Incident Classification

**True Positive**

## Escalation Required?

**No**

## Case Report

### Time of Activity

`09/08/2026 19:55:30.445`

### Affected Entities

| Entity | Details |
| :--- | :--- |
| **User** | `armaan.terry` — Sales |
| **Source Host** | `Lin-013` — `192.168.0.22` |
| **Destination IP** | `193.117.166.24` |
| **Destination URL** | `http://slak.com` |
| **Device / Service** | Firewall |

### Reason for Classifying as True Positive

The alert was triggered by the firewall's `Block-Phishing-Sites` rule when internal host `192.168.0.22` attempted to access the phishing website `http://slak.com`.

The asset inventory identifies `192.168.0.22` as `Lin-013`, the workstation assigned to **Armaan Terry** in the Sales department. The connection was directed to external IP `193.117.166.24` over TCP port `80`.

The firewall identified the destination as a **phishing website** and successfully blocked the connection. Because the user attempted to access a genuinely malicious phishing resource, the alert represents a **True Positive** even though the security control successfully prevented access.

### Reason for Not Escalating the Alert

Escalation is not required because the firewall successfully **blocked the phishing connection before the malicious website could be accessed**. There is no evidence in this alert of successful access, credential compromise, malware execution, or additional malicious activity on `Lin-013`.

According to the SOC escalation guidelines, successfully blocked phishing activity that causes no further impact does not require escalation.

### Recommended Remediation Actions

- Close the alert as a **True Positive with no escalation required**.
- Continue monitoring `Lin-013` for additional suspicious activity that could indicate successful phishing or compromise.
- Consider providing targeted **security awareness training** to `armaan.terry` regarding suspicious and unverified external links.
