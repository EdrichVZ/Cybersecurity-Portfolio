# Alert 1017: Shell Invocation via Apt

**False Positive**

## Escalation Required?

**No**

## Case Report

| Entity | Details |

| **Current Directory** | `/home/yani.zubair` |

### Reason for Classifying as False Positive

The alert was triggered by the execution of the `apt-get upgrade` command on `Lin-005`. The detection rule monitors the use of `apt` and `apt-get` because these utilities can potentially be abused to execute shell or proxy commands.

In this case, the command `apt-get upgrade` is a **standard Linux package management command used to upgrade installed packages to their latest available versions**.

This activity also follows Alert 1016, where `apt-get update` was executed on the same host. The sequence:

`apt-get update` → `apt-get upgrade`

is consistent with normal Linux system maintenance, where package information is updated before installed packages are upgraded.

No evidence in this event indicates that `apt-get` was used to invoke a shell, execute a proxy command, or perform unauthorized command execution.

### Reason for Not Escalating the Alert

Escalation is not required because the observed activity is consistent with **legitimate system administration and package maintenance**.

The command was executed as `root`, which is expected because upgrading system packages requires elevated privileges. The activity also occurred from `/home/yani.zubair` on the same host involved in the preceding legitimate `apt-get update` activity.

No additional indicators of compromise or malicious shell execution were identified.

### Recommended Remediation Actions

- Close the alert as a **False Positive**.
- No immediate remediation is required.
- Continue monitoring `Lin-005` for abnormal use of `apt` or `apt-get`.
- Correlate package-management alerts with surrounding activity before escalating.
- Consider tuning the detection rule to reduce alerts for normal commands such as `apt-get update` and `apt-get upgrade`.
