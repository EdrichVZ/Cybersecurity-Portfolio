# Alert 113: Outbound HTTP Connection

**Incident classification:** False positive
**Does this alert require escalation?:** No

## Case Report

### Time of Activity

**09/11/2026 11:00:51.952**

### List of Affected Entities

| Entity          | Details                                                                      |
| --------------- | ---------------------------------------------------------------------------- |
| **User**        | `TRYHATME\Amanda.Lee` (Finance Manager)                                      |
| **Workstation** | `FINANCE2-TRYHATME` (IP: `10.0.2.18`)                                        |
| **Process**     | `C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe` (PID: `7874`) |
| **Destination** | External IP `110.212.209.168` (Port `80` / HTTP)                             |

### Reason for Classifying as False Positive

The alert triggered due to standard outbound web browsing activity on HTTP port 80 initiated directly by Microsoft Edge (`msedge.exe`).

Cross-referencing company documentation confirms Amanda Lee is an authorized Finance Manager operating workstation `FINANCE2-TRYHATME`.

Outbound web requests originating directly from a legitimate browser binary without process injection or malicious command arguments represent routine web browsing.

### Reason for Escalating the Alert

**N/A (No escalation required).**

### Recommended Remediation Actions

Tune detection logic to exclude standard browser binaries (`msedge.exe`, `chrome.exe`, `firefox.exe`) establishing standard HTTP/HTTPS egress connections during operational hours.

### List of Attack Indicators

**None (Legitimate user web browsing activity).**
